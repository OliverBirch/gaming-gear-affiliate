Core Rules

Source of Truth

  • Zod schemas in src/lib/types.ts are canonical
  • Data files must conform — transform layers map raw JSON to schemas
  • Never edit raw data inline; create a transform layer
  • Pattern: see src/data/mousepads.ts

Product Copy (CopyPoints)

  • Prices in offers[].prisDkk or prices.json overrides only
  • No price strings in fordele, ulemper, or beskrivelse
  • Zod refine rejects $ + digit patterns at validation

Retailers

  • RETAILER_SLUGS is a closed Zod enum
  • Adding requires: update union in types.ts + add entry in retailers.ts
  • No slug before the retailer entry exists

Route Naming

  • Danish for routes and UI: /tastaturer, /musemaatter, /mus
  • English for code identifiers
  • Affiliate links: rel="sponsored nofollow", route via /api/redirect

Data Workflows & Skills

add-pro

Handles prose settings, peripherals, images, team data (Liquipedia), and stub mouse creation. Unknown mice tracked in mice-todo.ts.

add-mouse

Sources specs from RTINGS → Techpowerup → manufacturer. Copy from multi-source synthesis. Offers from affiliate portals.

add-headset

Mirrors add-mouse. Research specs → write Danish copy → find MaxGaming URL → add to JSON.

re-verify-pros

Batch re-checks pro gear from prosettings.net. Uses freshness-priority.ts for tier-1 prioritization.

fix-issues

Reads embedded issues.json from /admin. Auto-fixes: broken-url, missing-image, missing-pro-image.

Freshness Tickets

Incomplete data creates FreshnessTicket in freshness-tasks.ts. View at /admin/tickets.

Peripheral Mapping Gotchas

Short terms are greedy: "rog" matches both ROG Delta II and ROG Pelta. Prefer "delta" + "rog" over "rog" alone.
False positives: "cloud ii" matches HyperX Cloud Stinger II. Exclude with !includes("stinger").

Verify: Always check a handful of actual pro entries after adding a new matching pattern to catch false matches. Mapping file: src/data/pros-peripherals-mapping.ts
